# 심사 기준 (Rubric) — JNJ Dash / AI Judge

> **버전**: 1.0 · **작성일**: 2026-07-28 · **승인일**: 2026-07-28 · **상태**: ✅ 승인됨
>
> 이 문서는 AI Judge 의 **모든 지표·코멘트·감점 판정의 단일 기준**이다.
> 임계값·감점 코드·코멘트 규칙은 여기에서만 정의하고, 코드는 이 값을 복사해 쓰지 않고 참조한다
> (`worker/thresholds.py` 가 유일한 코드 측 소유자이며 본 문서의 값을 그대로 옮긴다).

---

## 1. 적용 범위와 AI 권한

### 1.1 4개 심사 축

| 축 | 정의 | 사람 심사 | **AI 점수화** |
|----|------|:--------:|:------------:|
| **Timing** | 음악의 비트와 동작 온셋의 시간적 일치 | ✅ | **✅ 허용** |
| **Technique** | 자세·중심 이동·프레임·풋워크의 완성도 | ✅ | ❌ **금지** |
| **Teamwork** | 리드/팔로우 소통, 커넥션, 상호 반응 | ✅ | ❌ **금지** |
| **Musicality** | 곡 구조(브레이크·코러스·악센트)에 대한 해석 | ✅ | ❌ **금지** |

### 1.2 AI 권한 규칙 (절대 원칙)

1. **AI는 Timing 축에만 정량 점수(`onbeat_ratio`)를 부여한다.**
   Technique / Teamwork / Musicality 에 대해서는 **관찰된 사실과 개선 제안(문장)만** 생성하며, 점수·등급·별점·백분율·순위를 어떤 형태로도 산출하지 않는다.
2. **모든 분석 결과에는 `confidence`(high/medium/low)를 포함한다.** `low` 면 지표를 표시하지 않고 재촬영을 안내한다 (§6).
3. **AI는 순위·합격/불합격을 판정하지 않는다.** 본 문서의 어떤 수치도 등수 산정이나 통과 여부 판단에 사용되지 않는다.

`sync_index`(파트너 싱크로), `activity_index`(음악 반응도)는 **참고 지표**이며 점수가 아니다. 화면에는 항상 "참고 지표" 라벨과 함께 표시한다.

## 2. Timing — 정량 기준 (AI 점수화 대상)

### 2.1 오프셋 정의

동작 온셋(관절 속도의 국소 최대점)에서 **최근접 비트까지의 부호 있는 시차(ms)**.

| 부호 | 의미 | 태그 |
|:----:|------|------|
| `+` | 비트보다 **늦음** | `lag` (밀림) |
| `−` | 비트보다 **빠름** | `rush` (당김) |

### 2.2 판정 임계값 — 템포 상대 기준

절대값 고정은 빠른 곡에서 지나치게 관대해지므로, **비트 간격 비율과 절대 하한 중 큰 값**을 쓴다.

```
beat_interval = 60000 / BPM          (ms)

T_onbeat = max(50,  0.10 × beat_interval)      # 초록 — 온비트
T_minor  = max(100, 0.20 × beat_interval)      # 노랑 — 경미
그 이상                                          # 빨강 — 오프비트
```

| BPM | beat_interval | T_onbeat | T_minor | 비고 |
|----:|--------------:|---------:|--------:|------|
| 80 | 750.0 ms | 75.0 ms | 150.0 ms | 비율 적용 |
| 96 | 625.0 ms | 62.5 ms | 125.0 ms | 비율 적용 |
| 120 | 500.0 ms | 50.0 ms | 100.0 ms | 비율 = 하한 |
| 140 | 428.6 ms | 50.0 ms | 100.0 ms | **하한 적용** (비율은 42.9ms) |

> 표의 값은 반올림하지 않은 정확한 계산값이다. 코드는 float 로 비교하며 ms 정수로 절사하지 않는다.

### 2.3 온비트율

```
onbeat_ratio (%) = count(|offset| ≤ T_onbeat) / total_onsets × 100
```

`reports.onbeat_ratio` 에 저장되는 **유일한 점수**다.

### 2.4 코멘트 톤 구간 — ⚠️ 등급 아님

아래 구간은 **코칭 문장의 어조를 고르기 위한 참조표**일 뿐이며, 등급·순위·합불 판정에 사용하지 않는다. 화면에 구간 이름을 표시하지 않는다.

| onbeat_ratio | 코멘트 어조 |
|-------------:|-------------|
| ≥ 90 | 유지 중심. 세부 구간의 미세 편차만 짚는다 |
| 75 ~ 90 | 강점을 먼저 인정하고 반복되는 패턴 1~2개를 지적 |
| 60 ~ 75 | 가장 빈번한 오프비트 유형 1개에 집중해 구체적 연습법 제시 |
| < 60 | 기초 카운트 연습을 권하고, 개별 구간 나열 대신 전체 패턴을 설명 |

## 3. 오프비트 구간 분류

### 3.1 구간 성립 조건

`|offset| > T_onbeat` 이고 **부호가 같은 동작 온셋이 연속 3개 이상**일 때 하나의 구간으로 묶는다.

### 3.2 구간 유형 (`type`)

| type | 조건 |
|------|------|
| `lag` | 구간 평균 offset > 0 (밀림) |
| `rush` | 구간 평균 offset < 0 (당김) |
| `break_ignored` | 음악 RMS 하위 20% 구간과 50% 이상 겹치는데 활동량이 직전 구간 대비 감소하지 않음 |

### 3.3 원인 추정 컨텍스트 (`context`)

| context | 판정 | 코칭 방향 |
|---------|------|-----------|
| `post_turn` | 구간 시작 2초 이내 턴 감지 (어깨-골반 orientation 누적 회전 ≥ 180°) | 턴 마무리 시점의 축·시선 처리 |
| `music_break` | 구간이 RMS 하위 20% 구간과 50% 이상 중첩 | 브레이크에서 멈추거나 악센트에 반응하기 |
| `chorus_entry` | 온셋 밀도 급증 경계 ±1초 | 코러스 진입 시 카운트 재정렬 |
| `general` | 위 어느 것에도 해당하지 않음 | 반복 패턴 관점에서 서술 |

## 4. 감점 트리거

`metrics_json.offbeat_segments[].penalty_trigger = true` 조건. 화면에서는 해당 구간 카드에 `danger` 배지를 표시한다.

| 코드 | 이름 | 조건 |
|------|------|------|
| **P-1** | 연속 오프비트 | `|offset| > T_minor` 인 동작 온셋이 **연속 4개 이상** |
| **P-2** | 심한 이탈 | 구간 평균 `|offset| > 0.35 × beat_interval` (반박 가까이 어긋남) |
| **P-3** | 브레이크 무시 | `type = break_ignored` 구간이 존재 |
| **P-4** | 반복 패턴 | 동일 `type`(lag 또는 rush) 구간이 영상 내 **3회 이상** 반복 |

> **감점 트리거는 "이 구간을 주의 깊게 보라"는 표시일 뿐, 점수를 차감하지 않는다.**
> `onbeat_ratio` 는 §2.3 공식으로만 계산되며 트리거로 조정되지 않는다.
> 합불·순위 판정에도 사용하지 않는다.

## 5. 심사 기록 JSON 스키마 (`ai_judge.judge_scores.payload`)

사람 심사위원의 라벨을 축적하기 위한 스키마다. **AI는 이 스키마로 출력하지 않는다** — AI 출력은 §7 의 코멘트 스키마를 쓴다.

```jsonc
{
  "rubric_version": "0.1-draft",
  "axes": {
    "timing":     { "score": 8, "notes": "브레이크 직후 반복적으로 밀림" },
    "technique":  { "score": 7, "notes": "중심 이동은 안정, 프레임이 후반에 무너짐" },
    "teamwork":   { "score": 9, "notes": "리드 신호 수용이 빠름" },
    "musicality": { "score": 6, "notes": "코러스 진입 악센트를 놓침" }
  },
  "penalties": [
    { "code": "P-1", "start_tc": "00:00:21.400", "end_tc": "00:00:24.100", "note": "" }
  ],
  "overall_note": "",
  "judged_at": "2026-07-28T10:00:00Z"
}
```

### 5.1 필드 규약

| 필드 | 타입 | 규약 |
|------|------|------|
| `rubric_version` | string | 본 문서의 버전 문자열. 라벨의 기준 시점을 고정한다 |
| `axes.<axis>.score` | integer 0–10 | **사람 심사위원만 기록.** AI 는 이 필드를 절대 채우지 않는다 |
| `axes.<axis>.notes` | string | 자유 서술 |
| `penalties[].code` | enum | `P-1` \| `P-2` \| `P-3` \| `P-4` |
| `overall_note` | string | 종합 코멘트 |

### 5.2 의도적으로 존재하지 않는 필드

`total`, `total_score`, `rank`, `ranking`, `pass`, `is_pass`, `qualified`, `winner`
— **합산·순위·합불 필드는 스키마에 두지 않는다.** 4축 점수는 각각 독립적인 라벨이며, 합산 방식은 이 제품의 범위가 아니다.

## 6. 신뢰도(confidence) 기준

| 값 | 조건 (하나라도 해당) | 화면 동작 |
|----|---------------------|-----------|
| **low** | 포즈 추출 성공 프레임 < **80%**<br>인물 ID 스위칭 감지 (커플)<br>전신 프레임 이탈 구간 > **10%** | 모든 지표·코멘트를 **숨기고** "분석 불가 — 재촬영 안내" 표시 |
| **medium** | 포즈 성공률 80~90% 또는 전신 이탈 5~10% | 지표 표시 + 신뢰도 배지에 주의 문구 |
| **high** | 위에 해당하지 않음 | 정상 표시 |

`low` 사유별 재촬영 안내 문구:

| 사유 | 안내 |
|------|------|
| `pose_success_low` | 조명이 어둡거나 인물이 가려졌습니다. 밝은 곳에서 정면으로 다시 촬영해 주세요. |
| `id_switch_detected` | 두 사람이 자주 겹쳐 개별 추적에 실패했습니다. 카메라를 더 멀리 두고 촬영해 주세요. |
| `out_of_frame_high` | 전신이 화면을 벗어나는 구간이 많습니다. 머리부터 발끝까지 들어오도록 촬영해 주세요. |

## 7. AI 코멘트 생성 규칙

### 7.1 시스템 프롬프트에 고정할 문구

> 당신은 소셜댄스 코칭 어시스턴트입니다. 본 rubric 을 유일한 판단 기준으로 사용하십시오.
>
> - **Timing 축에만** 정량적 판정을 붙입니다. 제공된 `onbeat_ratio` 와 구간 데이터를 근거로 서술하십시오.
> - **Technique / Teamwork / Musicality 는 점수·등급·별점·백분율·순위를 어떤 형태로도 생성하지 마십시오.** 영상과 지표에서 관찰된 사실, 그리고 개선 제안만 문장으로 서술합니다.
> - 합격/불합격, 등수, 다른 참가자와의 비교를 언급하지 마십시오.
> - 지표가 뒷받침하지 않는 단정을 하지 마십시오. 확신이 낮으면 "…로 보입니다" 로 서술합니다.
> - 한국어로, 참가자를 존중하는 어조로 작성합니다. 지적 1개당 실행 가능한 연습 방법 1개를 함께 제시합니다.

### 7.2 축별 관찰 항목 (코멘트 소재)

| 축 | 관찰 항목 |
|----|-----------|
| **Timing** | 온비트율, 오프셋 분포(mean/p90), 반복되는 lag/rush 패턴, 구간별 context |
| **Musicality** | 브레이크·코러스 경계에서의 동작 변화 유무, 악센트 반응, 활동량 지표(참고) |
| **Technique** *(참고)* | 자세 안정성, 중심 이동, 상체·하체 정렬 — 키프레임 이미지 기반 관찰 |
| **Teamwork** *(참고)* | 커넥션 유지, 두 사람의 동작 시작 시차(참고 지표 `sync_index`) — 커플 모드만 |

### 7.3 출력 스키마

`docs/02-design/features/ai-judge.design.md` §3.5 `COMMENTS_SCHEMA` 참조.
**해당 스키마에는 숫자 필드가 존재하지 않으므로**, 모델이 Timing 외 축에 점수를 부여할 구조적 경로가 없다.
